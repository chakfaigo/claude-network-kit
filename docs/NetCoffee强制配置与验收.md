# Net.Coffee 强制配置与验收标准

核对日期：2026-11-05。依据：[Claude Code 稳定使用指南的 11 项建议](https://ip.net.coffee/claude/claudecode.html)。本文件是本项目部署、交付与后续修改必须遵守的验收标准，不是可跳过的阅读材料。

**可以使用中文系统、中文浏览器和中文 Claude 界面。语言不影响本标准；其余网络配置与验收不得因为“能打开网页”就跳过。** 不要求为使用官方客户端更改语言、伪造时区、清空账号或安装指纹浏览器。

**必须区分“代码有这条规则”“目标机实际规则已生效”“该客户端真实请求已验证”。未知或未测记为“待验收”，失败记为“不通过”，不能填“通过”。** 本文件新增的是强制交付要求；当前安装器没有自动执行全部人工验收，也没有自动锁定并发数。安装成功不代表本表全部通过。

## 11 项逐项落实

| 网页项目 | 本项目必须落实的要求 | 已有实现、限制与验收证据 |
|---|---|---|
| 1. 出口 IP | 使用自己的住宅/ISP线路，核对供应商、预期固定公网IPv4和服务适用地区；不把共享机房或普通前置当家宽 | 安装前两次出口检查、运行期固定出口检查。第三方IP属性/评分作为辅助，不能保证供应商分类或账号资格；保留脱敏核对记录 |
| 2. IP 稳定性 | Claude最终出口固定；不轮换、负载均衡或自动切到其他出口。出口不符必须阻断并调查 | expected_ip参与安装与健康检查；合法更换出口需重新验证，不可为消除错误随便修改。即使家宽动态IP可能正常，也不能当成不会触发限制的保证 |
| 3. 强制 TCP | 受保护业务使用TCP；不允许UDP/QUIC成为绕路通道；保留现有UDP限制 | 家宽SOCKS出站设network=tcp，TUN规则先拒绝UDP。浏览器WebRTC另测；出口检测页通过不等于所有UDP路径已验证 |
| 4. TLS 指纹 | 使用官方客户端、保持证书验证；如采用支持uTLS的代理协议，必须核对相应实现和它作用的那一层，不能随便添加未知字段 | 当前可选前置是VMess/WS且不含TLS配置，家宽出口为SOCKS5，不能直接套网页fingerprint:chrome。不得声明已把CLI或桌面端变成Chrome。若把“目标服务看到的TLS必须等同Chrome”作为额外硬指标，本版未实现，必须标记未满足，不能宣称完全符合网页字面要求 |
| 5. DNS 走代理 | Claude及受保护目标DNS经指定代理路径的加密解析器；检查DNS detour与实际出口，禁止受保护域名落到国内直连解析 | remote-dns使用DoH并绑定选定出站；国内域名与代理主机引导解析有单独local-dns，这是明确例外，不是全机零直连DNS。应用自带DoH、缓存、VPN变化也需复核；发现受保护解析绕路不放行 |
| 6. 禁用 IPv6 绕路 | 受保护路径IPv4-only，AAAA与IPv6绕路受控；不得为解决小功能问题随手开放全局IPv6 | 已有IPv4解析策略、AAAA处理与TUN IPv6拒绝规则，仍需检查系统/接口实际状态。不是断言每个本地接口都没有IPv6；局域网功能有兼容代价 |
| 7. Claude 单独分流 | 网页、API、认证、更新及实际使用功能的相关域名必须核对；浏览器、VS Code、CLI、桌面端分别验收 | 用当前官方网络文档与目标机实际请求复核名单。默认海外流量经家宽是补充保护，不能替代域名完整性审查；新增MCP/插件/远程模式单独检查 |
| 8. 优先于智能分流 | 受保护域名/IP规则必须在国内、普通服务和泛匹配放行规则之前；故障与Origin模式继续拒绝受保护目标 | 已有构造顺序与隔离测试。不得增加DIRECT/普通代理作为Claude失败兜底；不能只按浏览器进程或共享CDN整体分组 |
| 9. 保持连接 | 保留客户端正常keep-alive，避免频繁切节点/重启核心；以长回答、连接重建和中断日志验证 | 本包没有额外承诺强制开启所有层的连接复用；HTTP keep-alive不等于代理多路复用。保护状态变化会重建核心，可能中断普通连接，安全阻断优先于不断线 |
| 10. 控制并发 | 初次验收单任务；按本项目保守操作规则，同一出口活跃Claude任务不超过4个，包含多窗口/多设备/代理子任务，且始终服从更低的账号/服务限额 | 这是取自网页建议的操作上限，不是Anthropic官方统一阈值，也不是软件限流。无法掌握共享出口总并发时先解决统计和协调，不得声称满足。遇429按限额与重试策略处理，不轮换出口规避限制 |
| 11. 路径短且稳定 | 分别测直连家宽与前置家宽，最终出口一致；选择稳定、丢包少、首字与上传表现好的方案，避免无必要串联 | 同任务同模型对照至少3次，记录首字、断流/重试与上传。加前置只可能改善到家宽的路径；家宽供应商故障/模型生成慢不由前置自动解决 |

网页中的“换家宽IP不会触发风控”“Chrome指纹完全一样”“5个以内就是安全”等表述不是官方保证。这里必须执行的是可验证配置、保守使用规则和如实记录；不以未验证的风控说法代替技术证据。不能声称本版逐字实现了网页全部内容。

## 不满足时不得判为验收完成

以下任一情况不得开始把该客户端用于日常Claude业务：

- 真实请求的代理路径尚未核对，或已发现与预期不符。
- 家宽出口不符、健康状态陈旧、保护核心/PF状态未知。
- 受保护流量或其DNS存在直连、其他出口回落、未解释的UDP/IPv6路径。
- 保护规则被普通/智能分流抢先放行，或已停用关键保护。
- 只测了浏览器，却准备直接把CLI、桌面端或远端会话视为已通过。

目标机故障验收须在本机所有者知情的维护窗口进行，避免中断现用业务；未完成前保留“待验收”，不以模拟测试补勾。其他条目也必须记录实际证据或准确限制；TLS字面指标无法满足时必须明确注明，不能被“全部通过”掩盖。

## 必填本地记录

复制 [验收记录模板](验收记录模板.md) 到仓库外的本机私有目录填写。记录每项通过/不通过/待验收、证据时间、客户端版本和已知限制；不在公开GitHub提交真实IP、账号、原始日志或截图里的敏感信息。

安装者负责检查，交付者负责核对，后续维护/AI不得通过关闭保护让检查变绿。更新客户端、核心、线路、DNS、分流、VPN/TUN或执行环境后，重新验证受影响项目。

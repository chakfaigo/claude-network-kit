# 国内直连与完整分流配置

**必须保持：未命中更高优先级保护/协议限制的国内域名和国内IPv4走直连，不绕家宽或普通代理。受保护目标优先，不能因为被某个国内库误收录就放行。**

这是现有程序已经实现的策略，不是本次新增的路由改动。此前文档只概述“国内/局域网直连”，本页补齐具体配置、例外与核验方法。以[guard_config.py](../portable/src/guard_config.py)的构造结果为准。

## 1. 先看模式表

下表适用于核心正常接管、协议允许、目标未命中更前面的规则。DNS在下一节单独说明。

| 目标 | Home：有普通代理 | Home：只有家宽 | Origin：有普通代理 | Origin：没有普通代理 |
|---|---|---|---|---|
| Claude及其他受保护目标 | 固定家宽出口 | 固定家宽出口 | 拒绝 | 拒绝 |
| 家宽故障后的受保护目标 | 拒绝，不直接回落普通代理 | 拒绝，不直连 | 拒绝 | 拒绝 |
| 国内域名库命中 | direct直连 | direct直连 | direct直连 | direct直连 |
| 非受保护目标解析后命中国内IPv4库 | direct直连 | direct直连 | direct直连 | direct直连 |
| 私有局域网目标 | 核心规则允许direct，仍受PF/协议限制 | 同左 | 同左 | 同左 |
| 明确列出的普通服务，且未命中前面规则 | 普通代理 | 家宽 | 普通代理 | 直连 |
| 其余目标，且未命中前面规则 | 家宽 | 家宽 | 普通代理 | 直连 |

Home阻断状态只改变受保护目标的放行，不把剩余海外流量自动全部改走普通代理。家宽本身不可用时，仍指向家宽的其他服务也可能不可用。核心完全退出时，PF会限制普通程序外连，不能保证国内网站仍可访问。

**“直连”是受管核心从物理网络直接访问目标，不是让应用绕过TUN/PF。** 浏览器或应用先连127.0.0.1:10808，也可以由核心按国内规则直连；看到本地代理入口不代表最终绕海外出口。

## 2. 路由顺序不能调换

当前构造的 route.rules 按以下顺序执行；前面的终止动作优先：

1. sniff：尝试识别目标协议/域名。
2. port 53 → hijack-dns：接管DNS请求，不把它当普通UDP直接拒绝。
3. 其余UDP → reject。
4. IPv6目标 `::/0` → reject。
5. 受保护域名/后缀/关键词 → Home允许时residential，否则reject。
6. 受保护IPv4网段 → 同上。
7. ip_is_private → direct。
8. geosite-cn → direct。
9. resolve，strategy=ipv4_only，为后续IP规则提供解析结果。
10. geoip-cn → direct。
11. 仅Home且有upstream时：普通服务明确名单 → original。
12. final：Home及home_blocked为residential；Origin为original（有upstream是普通代理，无upstream是direct类型出站）。

**不得把CN直连、所有直连、普通代理、通配规则插到保护规则前。不得按网页中文、.cn后缀或整个Chrome/微信进程直接放行。** 软件可能同时访问国内业务、海外CDN和共享遥测，应按具体目标判断。

国内直连不等于所有国内协议都允许：UDP/QUIC及IPv6限制在国内规则之前，因此国内UDP业务、视频/语音、游戏或局域网发现也可能受影响。当前没有为这些功能逐应用开放的例外；不要为修复它们取消整个阻断策略。

## 3. DNS 分开配置，不是全机一个出口

| DNS用途/条件 | 当前配置 | 路径 |
|---|---|---|
| AAAA查询 | 预定义NOERROR响应，不返回可用IPv6地址 | 先于其他DNS规则 |
| Home开放时的受保护域名 | remote-dns | 1.1.1.1的DoH，经家宽所选路径 |
| Home阻断/Origin的受保护域名（除上述AAAA处理） | REFUSED | 不进行正常解析 |
| geosite-cn国内域名 | local-dns | 223.5.5.5的DoH，绑定物理接口直连 |
| Home有上游、命中明确普通名单 | ordinary-dns | 1.1.1.1的DoH，经普通代理 |
| DNS规则链其余查询 | final=remote-dns；唯独Origin无上游时为local-dns | remote-dns在Home经家宽、Origin有上游时经普通代理 |
| 家宽/上游服务器主机名引导解析 | domain_resolver=local-dns、ipv4_only | 防止递归依赖尚未建立的代理 |

`route.default_domain_resolver`同样设置为local-dns。路由的IP判定所需解析要结合该字段检查，不能只看dns.final便宣称所有未知域名解析必定走家宽。已识别受保护目标必须由前面的保护规则处理；未知域名或新功能需单独审核。

系统活动网络服务的DNS被设为1.1.1.1/8.8.8.8，是交给受管路径处理的系统入口；不能据此认定国内域名直接向这两个地址查询。实际DNS分流由核心决定。Chrome基线关闭的是Chrome自行选择的Secure DNS，核心DoH仍保留。

## 4. 同事要在哪里配置

### 普通使用者

不需要手写国内分流。完整解压本版本 → 填自己的线路 → 运行首次安装；随包的geosite-cn.srs、geoip-cn.srs和配置生成代码会装入保护目录。

国内直连没有单独开关，不需要把软件切到“全局直连”。也不要在Chrome、Clash或系统代理里再配第二套分流。公开包采用受管TUN；**macOS系统HTTP/HTTPS/SOCKS/PAC代理保持关闭**。Claude Code全局env仍指向本机10808，这两者不是同一个设置。

### 维护者

| 要改的内容 | 唯一应先审查的源位置 | 强制要求 |
|---|---|---|
| 国内域名匹配 | portable/assets/geosite-cn.srs | 核对来源、版本、摘要；不能只按站点语言判断 |
| 国内IPv4匹配 | portable/assets/geoip-cn.srs | 核对CIDR和实际归属；共享CDN归属可能变化 |
| 普通代理服务名单 | guard_config.py中的ORDINARY_SUFFIXES/ORDINARY_DOMAINS | 保持在保护与国内规则之后；没有upstream时不生效 |
| 受保护范围 | SUFFIXES/DOMAINS/KEYWORDS/IPS及targets() | 核对共享域名的影响，新增功能不得靠默认路由替代保护审查 |
| DNS和路由顺序 | guard_config.py的build() | 保持上述顺序、所有模式一起检查 |
| 真实线路信息 | 目标机自己的配置入口 | 不提交公开GitHub，不把真实信息写进源码或示例 |

当前普通代理后缀：openai.com、chatgpt.com、oaistatic.com、oaiusercontent.com、notion.so、notion.site、notion-static.com。精确域名：update.code.visualstudio.com、marketplace.visualstudio.com、vscode.download.prss.microsoft.com、vscode.blob.core.windows.net。其他网站不会因为“不是Claude”而自动进入普通代理名单。

本包规则库是固定本地快照，不自动下载更新。来源说明只保留了沿用原方案的信息，没有完整记录原始规则库的上游提交/发布日期，因此**不能宣称它是最新全国全量名单**。当前分发摘要见manifest；将来更新必须补齐来源/版本和变更记录。

修改源码/规则文件后必须更新manifest、运行相关隔离测试与核心语法检查、验证保护优先级，再发布新的完整包。**已经安装的电脑不会因为下载新ZIP、改解压目录或点Home就自动升级。** 当前没有通用热更新器/迁移器；不要直接编辑root目录的bundle、活动config或覆盖备份。已装目标机须另行准备与当前状态匹配的更新及恢复步骤。

## 5. 怎么验收国内直连

1. 核对目标机实际加载的国内规则摘要与分发版本一致，记录在本地。
2. 选择实际要用的国内域名、国内IPv4样本、普通代理服务、Claude目标和未知海外目标，分别记录规则命中、DNS路径和实际连接。
3. 域名命中、IP命中是两个检查；网站能打开或ping能通都不能证明它走了直连。若只拿到规则库离线结果，明确写“离线命中”，不能当实际路由证据。
4. 对Home与Origin分别核对；协议限制和保护优先级必须保留。不要为了验收绕开PF或切全局直连。
5. 默认核心日志级别是warn，诊断不导出每个请求的完整路由。不能要求从默认健康日志读出不存在的逐请求证明。需要时由维护者在受控窗口使用官方规则匹配工具、适当日志或受控目标的服务端记录，完成后恢复日志级别并脱敏。

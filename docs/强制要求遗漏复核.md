# 强制要求遗漏复核 · 2026-11-05

复核范围：GitHub main、安装/配置/用户入口、健康判定、通知、现有测试与文档。本轮不读取或上传任何真实凭据、不修改网络行为。既有国内直连、保护优先、DNS、Chrome和恢复要求保留，新增统一的[必须执行的部署流程](必须执行的部署流程.md)。

| 原先容易遗漏或误解的点 | 本次补成的强制要求 | 对应实际依据 |
|---|---|---|
| 全局settings有代理就算完成 | C2：核对真实进程、大小写变量、NO_PROXY、自定义配置目录、项目/托管设置与启动参数 | controller.install_proxy_preferences只合并一个全局文件，不枚举所有客户端环境 |
| 其他代理关窗口就算退出 | A4、E4：检查登录启动、后台与扩展接管，变更后复验 | 安装器preflight/snapshot只检查当时状态，不承诺后续不会被其他软件改写 |
| 一键安装/切换失败就是无变更 | B2、B5及失败分级：停止反复点，先看本次状态/日志 | guard_install.switch先提交意图并启动服务，后续仍可能失败；用户注册步骤也可能在网络运行后失败 |
| 核心健康就算提醒/Chrome也已完成 | B5、C1、D4：分别确认菜单/通知到达/Chrome策略 | 用户入口分步注册，Chrome策略不由安装器写入 |
| 绿色健康等于两个探测都成功 | D5：把出口判定与链路质量分开记录，不能掩盖另一探测超时 | guard_health.decide_health允许None与预期IP并存，但错误出口优先阻断 |
| root下试通就算普通客户端可用 | C2–C5：普通用户验收，禁止sudo运行Claude作为绕行修复 | guard_pf.render_anchor包含root网络例外 |
| 开盖成功就算重启自动启动通过 | D3：客户端重开、睡眠/唤醒、换Wi-Fi、系统重启分别记录 | runtime.run的唤醒检测与系统LaunchDaemon/用户LaunchAgent启动不是同一测试 |
| 新协议/网关/后台任务自动继承验收 | C3、C5：请求目标与执行位置变更，必须扩大范围后重新验收 | 固定目标规则和本机TUN不能自动覆盖其他主机/未知网关 |
| 要求写了但没有明确负责人与失败动作 | A–E编号、每项证据、停止条件、签收责任及日常复验 | 这是本轮补充的操作流程，不宣称是新增自动拦截代码 |

## 仍需明确保留的未实现/未验证项

- Chrome策略须在目标机通过受支持方式配置，不能以网络安装成功代替。
- 人工并发上限、部署签收与变更复验不是软件自动门禁。
- 首次安装包不是通用升级器/卸载器；当前没有一键安全故障试验工具。
- 国内规则是固定快照，来源日期不完整；离线匹配样本不覆盖全部国内站点，也不等同真实路径。
- 同事机器的真实断网/错出口/重启/应用请求仍待实际验证。历史188项隔离测试不证明这些场景已经通过。
- 普通用户保护不防root或管理员主动绕过，监控存在轮询延迟与启动窗口。

本轮新增的是可执行、可核对的部署规范；未发现需要为了这些文档要求而立即改动现用网络的依据。不能据此宣布没有任何遗漏或永远不会故障；新的功能与环境必须按流程纳入复核。

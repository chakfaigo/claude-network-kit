# 必须执行的部署流程

本页规定公开同事版的执行顺序、证据和失败处置。安装者、交付者、后续维护者及协助操作的AI必须遵守；不能用“按经验应该没事”代替检查。配置细节以[完整清单](完整配置清单与交付门槛.md)、[分流规范](国内直连与完整分流配置.md)、[Net.Coffee标准](NetCoffee强制配置与验收.md)和[Chrome专项](Chrome专用配置与验收.md)为准。

**这里是强制操作和交付规则，不是软件已经实现的自动门禁。** 当前程序不能阻止管理员改设置、阻止用户提前打开所有客户端，或替人完成Chrome策略配置。操作者必须遵守；未完成就不能交付为“可日常使用”。

## 先约定责任与证据

- 指定这台电脑的安装执行者和交付复核者；可以同一人承担，但必须分别填写执行结果和复核结论，不得虚构第二人。不会核对的项目记待验收，交维护者处理。
- 验收只覆盖明确列出的客户端、资料目录、账号认证方式、物理接口和网络环境。未安装/未使用的客户端可写“不在本次范围”，以后启用前必须补验，不能默认继承别人的结果。
- 每项必须记录日期、版本、实际结果、证据所在的本地位置、失败/待办和负责人。证据可以是脱敏截图、具体命令检查结果或实际连接记录；不能只写“通过”。真实账号/出口/原始日志保留本机，不上传公开仓库。
- 中文可以保留。强制复制的是已核对的保护原则和本版本参数，不是其他电脑的语言、时区、节点、私人账户或旧脚本。

## 阶段 A：安装前，必须全部确认

| 编号 | 必须完成 | 证据与停止条件 |
|---|---|---|
| A1 | 从本仓库当前Release取得完整原始包，核对版本、SHA-256与完整性 | 缺文件、混用旧脚本、摘要不符立即停止；不运行来历不明的“修复包” |
| A2 | 确认Apple Silicon、macOS13+、首次安装状态和管理员维护条件 | 有旧保护、未知PF、VPN/TUN、系统代理或端口/接口冲突，先处理来源，不删除旧状态硬装 |
| A3 | 确认自己的线路、协议、预期出口及供应商允许的使用方式 | 不复用分享者凭据，不把网关IP猜成出口，不用轮换出口；已有上游要核对字段与美国出口约束 |
| A4 | 检查其他网络管理者及登录启动项 | 本机只保留本方案作为当前网络控制者；其他VPN/Clash/v2ray/代理扩展/MDM若会自动接管，必须确认停用或兼容方案。不能只关窗口便宣称已消除冲突，不强制删除企业策略 |
| A5 | 保存工作，约定维护窗口与本机恢复手段 | 远程桌面可能中断，目标机需有人能处理管理员授权与日志；没有恢复条件就暂停安装，禁止拿正在进行的业务当故障试验 |

此阶段不得先打开真实Claude任务“试一下能不能用”。安装器自身的线路检查使用公开探测目标，不需要Claude账号。

## 阶段 B：按原入口安装，不允许跳步

| 编号 | 必须完成 | 证据与停止条件 |
|---|---|---|
| B1 | 普通用户运行配置入口，凭据仅保存在本机私有文件 | 不用sudo启动整个用户入口，不覆盖已有node，不截图或粘贴密码到Issue |
| B2 | 普通用户运行一次安装入口，等待线路检查和管理员步骤结束 | 不并行启动安装/Home/Origin，不反复点按钮、不杀持锁进程或删除锁文件；失败先保留该次日志 |
| B3 | 核对本机备份、已安装版本、10808、utun99与绑定物理接口 | 程序/核心/备份不是同一安装版本、备份不可用或接口冲突则停止；不临时换成别的端口蒙混过关 |
| B4 | 核对TUN、活动PF、系统代理关闭、系统DNS/IPv6与受保护优先级 | 不能只看配置文件存在；不把系统代理打开填10808，不以“国内直连”取消保护 |
| B5 | 等待本次Home请求的新状态与两轮验证，菜单/提醒/日志均完成 | 旧绿色菜单、旧request、过期状态、仅有核心进程均不算通过。网络已运行但菜单/提醒失败，也不能宣布安装全部完成 |

如果入口报错，**不等于所有操作已回滚**：可能已写模式请求、建立PF或启动部分组件。必须记录当前模式、状态、时间与日志，判断是“安装前失败”“已发布但附属步骤失败”还是“部分安装”；禁止统一用删除目录、关闭PF或重跑安装解决。判断不了就停止并交维护者处理。

## 阶段 C：真实客户端配置，必须逐个核对

| 编号 | 必须完成 | 证据与停止条件 |
|---|---|---|
| C1 | Chrome按专项配置策略并完全重开，核对日常使用的资料目录 | QuicAllowed=false、DnsOverHttpsMode=off、WebRtcIPHandling=disable_non_proxied_udp须实际生效；本包不自动设置，不能只凭JSON或页面开关填通过 |
| C2 | 检查CLI/VS Code/桌面端实际启动环境及配置覆盖来源 | 逐项核对进程代理大小写变量、NO_PROXY、全局/项目/托管配置、启动参数、扩展与CLAUDE_CONFIG_DIR；不以全局settings文件内容代替最终生效值 |
| C3 | 明确官方认证方式和请求目标 | 不添加未知ANTHROPIC_BASE_URL、第三方网关或他人Key；新供应商/网关不在当前保护验收范围，先审核域名与路径再使用。不能一边改认证/计费一边当成只改代理 |
| C4 | 保持证书验证，检查工具执行权限与扩展能力 | 禁止用NODE_TLS_REJECT_UNAUTHORIZED=0、忽略证书错误等作为修复；不默认启用bypassPermissions/危险跳过权限，不把全局部署/合并授权照抄给新机器 |
| C5 | 每个实际使用的客户端都测新请求、DNS与分流 | Chrome、VS Code、CLI、桌面Chat、Local Code分别记录；SSH/Cloud/Cowork、MCP、后台代理和子进程按实际执行位置另验，不能因主界面成功就签收全部 |

C2至少检查：HTTP_PROXY/HTTPS_PROXY及小写变体应与本机入口一致；NO_PROXY不能是`*`或排除受保护域名；ALL_PROXY不能成为Claude Code唯一依赖；自定义CLAUDE_CONFIG_DIR不能悄悄跳过全局保护env；旧后台进程可能保留旧环境，改完配置要按该客户端方式重开并复核。只记录变量是否存在及脱敏目标，不整份输出环境，以免泄漏Key。

所有网络验证都用普通用户运行客户端。**禁止用sudo运行Claude来让网络通**，因为PF允许root网络操作，不能把root路径当普通用户路径已通过。

## 阶段 D：分流和故障验收，缺项不得签收

| 编号 | 必须完成 | 必须得到的结论 |
|---|---|---|
| D1 | 国内域名/IP、普通名单、受保护目标、未知海外目标分别核对 | 国内按规则直连；保护优先；普通名单与默认出口符合本版本；DNS路径对应正确 |
| D2 | 实机核对家宽不可达、出口不符、Origin、核心退出与恢复 | 受保护请求不能改走直连/其他出口；恢复重新验证；不为造故障直接解除PF，不用更改预期IP掩盖错误 |
| D3 | 完全退出重开客户端、睡眠唤醒、换Wi-Fi及重启后核对 | 新状态、新请求、新规则证据；只测开盖不能代替重启。换物理网卡需先处理接口绑定，不假定自动迁移 |
| D4 | 在受控故障/恢复中核对本机提示、菜单和日志 | 通知真实可见、状态足够新鲜；通知权限关闭或专注模式抑制须记录，不能仅以“已登记启动项”代替实际到达 |
| D5 | 区分出口健康与连接质量 | 当前健康判定允许一轮中至少一个预期出口成功、且无错误出口/无效结果；另一探测超时仍可能进入健康。须记录失败探测与重试，不能把绿色状态说成两条检测均无故障 |

故障试验必须由维护者在目标机所有者知情的维护窗口设计并记录触发与恢复方式。本仓库没有一键安全故障注入工具；不熟悉的同事不得随意停服务、修改防火墙或伪造状态文件试验。没有条件完成就保留待验收，不用188项隔离测试或其他电脑的成功结果补勾。

## 阶段 E：签收与日常保持

1. 执行者填写[验收记录](验收记录模板.md)，复核者检查A1–D5及全部适用专项；任何失败/待验收项不能写“部署完成”。不在范围的功能必须明确列出、禁止未经补验直接启用。
2. 保存本机备份、安装版本、日志位置、已知限制、故障联系与维护方式。不能只交一个ZIP和“应该能用”。
3. 每次开始使用Claude，先看当前Home状态与更新时间；发现过期、禁用、错误出口或配置漂移，暂停新任务，检查原因，不先关保护试通。开机服务启动前的窗口不能当已保护状态。
4. 客户端/Chrome自动更新、策略变化、扩展更新、系统升级、线路/IP/规则变化、VPN变化和接口切换后，先记录变化并复验受影响项。不要为规避复验长期关闭安全更新；更新后验证。
5. 异常处置顺序：保存时间和错误 → 暂停相关任务 → 查看新状态和脱敏诊断 → 定位供应商/线路/DNS/规则/客户端/认证层 → 按本机备份与专项方案处理 → 重新验收。禁止随机切IP、开启全局直连、放开UDP/IPv6、取消证书验证或清空账号当作通用修复。
6. 已装机器下载新版不等于升级；文档更新不用重装网络，程序/规则/线路变更需专项迁移。Origin不是卸载，不允许复制他机备份恢复。

## 不能被“强制要求”掩盖的事实

没有自动Chrome策略部署、没有自动并发限流、没有通用升级/卸载/故障注入器；规则快照的上游日期未完整追溯；目标机实际验证也未由仓库替你完成。Chrome TLS伪装和账号无风控不能作为已兑现承诺。以上必须在交付记录中保留；增加“必须”字样不会让未实现功能自动出现。

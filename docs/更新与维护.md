# 已安装电脑的更新与维护

首次安装器会拒绝覆盖已安装目录，这是保护措施。下载新版、改解压目录或点击Home不等于已安装版本更新。本版仍没有面向所有旧状态的自动迁移器；新机安装包已包含本次修复，旧机需要针对现有状态制定维护步骤。

## 先识别，避免误装

从新包运行`portable/接入检查.command`，它可以只读比较已安装控制器/生成器与新包源码。不同意味着需要核对，不能直接宣布哪一份正确，也不能因此删除安装目录。检查脚本不读取旧机private凭据。

主仓库此前版本缺少`claude.app`显式保护，且有临时预检解析与用户服务登记问题。只下载新文档不会修复旧机。另一台电脑已经手工打补丁，也不代表所有变更与正式版一致。

## 维护者必须形成可审查的更新单

记录当前安装来源、源摘要、是否已有本地补丁、接口与模式、当前活动保护和自己的备份。确认维护窗口、现场管理员条件、可恢复路径。真实凭据、bundle和备份保留原机私有位置，不在公开仓库或聊天传递。

对配置生成器的更新必须同步核对源、bundle、全部派生配置、DNS及活动配置；无上游3份，有上游5份。保留原始安装备份，维护备份单独保存。先用虚构身份隔离测试和交付核心校验，再进行与目标状态匹配的迁移；失败必须知道哪些已写入、哪些已启动，不能假定自动全部回滚。

对控制器的更新必须验证完整入口、模式结果、菜单/提醒登记、CLI设置及失败恢复。不能只试核心切换；提醒登记也不能替代通知显示。

维护后核对新鲜状态、普通用户新请求、实际保护与变更涉及的故障场景，记录新来源/摘要；未完成仍不得签收。没有对应迁移方案时保持待维护，不直接复制脱敏学习包源码、覆盖root文件或借用其他电脑备份。

## 仓库维护与发布

- 使用`python3 -B tests/run_checks.py`运行隔离逻辑测试；Apple Silicon发布机器另加`--core`完成禁网核心检查。已登录的Mac还可显式加`--user-agents`，建立并清理独立命名的sleep/true临时服务，验证真实launchd；不会操作生产保护服务。CI自动跑逻辑回归，不能替代目标机验收。
- 涉及portable的变更更新版本、manifest、变更记录和新Release；不覆盖旧Release。
- 发布前校验密钥/个人信息、文档链接、ZIP文件权限/符号链接、摘要和上传内容；只从Git已跟踪的审查结果打包。
- 内置国内规则仍是固定快照，不自动更新；新增域名、功能、协议或规则来源必须另审，不把域名清单当永不变化的事实。

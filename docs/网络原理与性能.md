# 网络原理与性能

分流决定“哪些目标走哪条线路”；链式代理决定“如何到达家宽”。二者独立。

| 方案 | 普通服务 | Claude |
|---|---|---|
| 分流＋直连家宽 | 电脑 → 普通代理 → 服务 | 电脑 → 家宽 → Claude |
| 分流＋前置家宽 | 电脑 → 普通代理 → 服务 | 电脑 → 普通代理 → 家宽 → Claude |

增加前置不会让普通代理变成家宽；Claude 最终的出口仍必须是家宽。若瓶颈在电脑到家宽的跨境连接，前置可能改善丢包、连接建立和卡顿；若瓶颈在家宽供应商、家宽到 Claude，或模型生成，前置不一定有效。多一跳也可能变慢。

测速比较首字响应、长回答中断/重试、上传时间，尽量同模型、同任务、相近时段重复观察；不要只用下载测速解释模型生成速度。供应商维修应确认具体故障段，不能用一个“美国 IP”或评分证明线路稳定。

## 本包实际策略

Home 下：受保护域名/IP优先走家宽；国内/局域网按规则直连；有上游时 OpenAI、Notion 和明确列举的 VS Code 更新/下载域名走普通代理；其他海外流量默认走家宽。它不实现“除 Claude 外全部走上游”。要扩大普通服务名单，应单独审查，不能使用整个浏览器进程或共享 CDN 来代替服务边界。

受保护名单还含部分遥测、客服共享域名及关键词，因此可能影响非 Claude 应用对这些共享服务的使用。这是继承策略的覆盖代价，并不表示这些域名都专属 Claude。

无上游时不能凭空获得普通代理分流。有上游时，已选 Home 路径发生故障后会阻断并按已选路径检测，不通过普通代理直接访问 Claude；手动 Home 才按其流程重新选择路径。

## 保护证据与边界

系统代理/HTTP 变量是应用接入方式；TUN 捕获路径；PF 限制自然回落；健康检查检测出口和恢复；通知报告变化。这些不是一个功能，也不是打开 TUN 就全部完成。

检查有轮询间隔：退出或出口变化并非每个请求实时鉴定。未知第三方转发、管理员主动改规则、开机服务启动前窗口、远端任务和新出现的域名需要另行评估。TCP、UDP、IPv6的覆盖需要实际规则与连接证据，不靠网页评分保证。

DNS 加密（DoH）与 DNS 经哪个出口是两回事。CLI 的 TLS 也不等于浏览器指纹；隧道外层 Chrome 指纹不会自动改变端到端的内层 TLS。

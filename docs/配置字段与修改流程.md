# 配置字段与修改流程

## 同事首次配置：只填自己的线路

使用完整Release中的 `portable/配置线路.command`，按提示填写。写入 `portable/private/node.json`（目录0700、文件0600）；不联网、不改系统、不覆盖已有文件。使用者无需手写国内分流或系统PF。

| 字段 | 必填/类型 | 说明 |
|---|---|---|
| server | 必填字符串 | 家宽SOCKS5服务器IPv4或DNS主机名；不是网站URL，不含协议前缀 |
| port | 必填整数1–65535 | 供应商SOCKS5端口，不是固定填写10808 |
| username | 必填ASCII字符串 | 自己的代理用户名；非Claude登录名 |
| password | 必填ASCII字符串 | 自己的代理密码，隐藏输入；不进入Git或命令参数 |
| expected_ip | 必填公网IPv4 | 供应商确认的最终固定出口；服务器IP和最终出口可能不同，不猜测 |
| upstream | 可选对象 | 不填则没有普通代理/前置；填写时协议严格受限 |

用户名与密码当前限制为非空ASCII、最大255字节、无控制字符。域名家宽/上游也会经local-dns做引导解析。动态轮换出口不符合本方案固定IP验证要求。

`portable/examples/node.example.json` 和 `upstream.example.json` 都是无效占位示例。尤其示例expected_ip是文档保留地址，会被校验拒绝，这是防止直接拿示例联网，不是安装器坏了。

## 可选上游的字段

先在仓库外私有目录准备自己的JSON，再在配置入口提供路径。也要保护这份源JSON，它包含身份信息。

| 字段 | 允许值/含义 |
|---|---|
| type | vmess |
| server / server_port | 上游主机和端口 |
| uuid | 自己的规范UUID，不借用分享者身份 |
| security | auto、none、zero、aes-128-gcm、chacha20-poly1305之一，必须与供应商一致 |
| alter_id | 0–65535整数，按供应商设置 |
| transport.type | ws |
| transport.path | 以/开头的WebSocket路径 |
| transport.headers | 可选，仅Host字段 |
| transport.max_early_data | 可选，0–65535整数 |
| transport.early_data_header_name | 可选，合法字母/数字/连字符字段名 |

当前不接受TLS、VLESS、Trojan、Shadowsocks、任意自定义detour或额外监听/路由字段；校验失败不应通过删除校验来强装。上游安装前要求公开检测结果为美国；这不是证明最终家宽也一定可用。

## 必须保持的固定基线

- 本地混合入口127.0.0.1:10808；TUN接口utun99。配置包绑定安装时识别的物理接口；换不同网卡/有线接口需要重新核对，不保证自动迁移。
- 受管TUN是浏览器等普通应用的接入路径；macOS系统代理基线关闭。本版不会把它设成10808。
- Claude Code的 `~/.claude/settings.json` env 合并HTTP_PROXY/HTTPS_PROXY及大小写变体，值为本机HTTP入口；ALL_PROXY为本机SOCKS入口，NO_PROXY仅本机回环。CLI自身不能仅靠SOCKS。
- 不自动写shell启动文件；从普通终端运行其他工具是否继承代理需要实际核对，不能复制别人的.zprofile覆盖自己的。
- 活动网络服务关闭IPv6，系统DNS入口设1.1.1.1/8.8.8.8；核心内的实际DNS分流见[国内直连文档](国内直连与完整分流配置.md)。
- Home/Origin都保留TUN/PF；安装前已有系统代理/VPN/其他PF规则不能强行覆盖。

## 维护修改必须成套进行

1. 先记录当前版本、摘要、配置来源、变更目的和适用目标机。真实节点保留在本机，源码用虚构测试值。
2. 用户线路变化与代码策略变化分开处理。配置入口不会覆盖已有node，首次安装器不会覆盖已有安装。公开版目前没有换线路热更新向导或通用升级器；已安装电脑必须由维护者核对现状、备份和回退方案后准备专项更新。
3. 分流修改只从配置生成源与规则资产开始，保持保护优先。不要手改正在运行的config.json、bundle.json或单个root规则文件；bundle有构造一致性检查，局部替换可能被拒绝，破坏恢复能力。
4. 涉及Home、Home阻断、前置Home、前置阻断和Origin的修改，必须同时检查全部存在的配置；前置预检查也不能遗漏。没有upstream的配置也必须仍可用。
5. 修改程序运行对应隔离测试；修改路由/资产用实际交付核心做语法与样本匹配检查，并核对国内规则不能覆盖保护范围。修改Chrome须用实际Chrome策略页验收。
6. 更新manifest、来源记录、文档、ZIP与SHA-256，扫描隐私，发布新版本。重新解压验证，不用改过且含凭据的工作目录打包。
7. 目标机在维护窗口实施并检查国内直连、普通代理、Claude、DNS、故障/恢复、开盖/重启。新Release发布不等于已装目标机自动更新。

## 安装和运行会留下哪些数据

| 位置 | 内容与用途 |
|---|---|
| /Library/Application Support/ClaudeResidential | 已安装程序、核心、运行时、菜单及public/private目录 |
| 其下private/before-guard | 本机原PF和网络设置、摘要；不是可公开上传的模板 |
| 其下private | 真实线路bundle、生成配置、选路与意图、私有探测日志 |
| 其下public/status.json | 菜单/提醒读取的公开状态字段；不是完整路由审计 |
| ~/Library/Application Support/HomeGuard | 操作日志、筛选诊断、before-user-settings.json备份 |
| ~/Library/Application Support/ClaudeResidentialWatch | 提醒状态记录 |
| /Library/LaunchDaemons/local.claude.residential.plist | 系统守护启动项 |
| ~/Library/LaunchAgents下相关local.claude.residential项目 | 用户菜单与提醒启动项 |
| /etc/pf.conf及对应local.claude-residential锚点 | 内核保护入口和规则 |

`导出诊断.command`需要管理员授权，会筛选字段，但可能含出口IP和时间。默认核心日志级别warn不记录每个请求的路由决策。健康日志按大小轮转；不要为了“更好排查”永久开放含请求细节的公开日志。
